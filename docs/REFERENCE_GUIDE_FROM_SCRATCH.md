# מדריך ייחוס חדש מאפס — חוזה מימוש

## גבולות
- מדריך חדש בלבד, עבור אפליקציות הדוגמה Web ו-Windows.
- אין העתקת GuideSteps, עוגנים, הקשרים או תנאי מעבר ממדריכים קיימים.
- אין שימוש במדריכי הדוגמה או בתוצאות בדיקותיהם כבסיס לתכנון.
- מספר השלבים נקבע רק לאחר בניית רצף פעולות תקין ומפת כיסוי יכולות.
- אין לשנות את מדריכי הייצור הקיימים.

## מקורות אמת
1. קוד המנוע והמודל: `src/DAP.Core`, `src/DAP.Runtime.Web.Extension`, `src/DAP.Runtime.Windows`, `src/DAP.Data.Sqlite`.
2. ממשק הדוגמה: `demos/Web/App/wwwroot` ו-`demos/Windows/App`.
3. התנהגות אמיתית בהרצה, לרבות DOM ו-UI Automation; מקור קוד הדוגמה משמש לתכנון בלבד ולא תלות של המנוע.

## נתונים שנבדקו בקוד
- מודל GuideStep כולל יעד אופציונלי, בועית, אימות, מצב התקדמות, הקשר, לכידה, תנאי השלמה ומפתח הקשר יישום.
- מודל StepCaptureTiming מכיל BeforeAction, DuringStep, AfterAction.
- ממשק Web כולל iframe לתוכן וכותרת, טופס חיפוש לקוח, תוצאות, מיון, ניווט ופעולות CRUD.
- ממשק Windows מגדיר AutomationId לרכיבי חיפוש ופעולות עסקיות ומספק שמות נגישים לשדות.

## רצף עסקי מתוכנן, נכתב מחדש
1. פתיחת יישום Web, זיהוי הקשר פעיל ומסגרת התוכן.
2. חיפוש לקוח באמצעות שדה טופס, הפעלת חיפוש, אימות תוצאות ומיון.
3. ניווט לרשומת לקוח, לאתר ולפנייה, עריכת ערך ושמירתו.
4. מעבר ליישום Windows, זיהוי חלון וחיפוש אותה ישות.
5. ניווט לרשומה, אימות מידע, שינוי נתון, שמירה והופעת משוב.
6. חזרה ל-Web, רענון ובדיקת הנתון המעודכן, וסיכום ללא יעד.

זהו שלד תרחיש בלבד. יש לפרט את כל המעברים והיעדים לפני יצירת מדריך.

## כיסוי חובה לתכנון
- כל שיטות האיתור הישימות בכל מנוע.
- כל יחסי העוגנים הנתמכים, כולל שילוב עוגנים.
- כל מצבי האימות וההשלמה שניתנים להדגמה בממשקי הדוגמה.
- שלושת מועדי הלכידה ושימוש בערך שנלכד.
- כל מיקומי הבועיות הנתמכים, הוראה ללא יעד, והתקדמות ידנית/אוטומטית.
- מסגרות Web, החלפת תוכן, רכיבים דינמיים, שינויים בעקבות אירוע, ומעבר Web/Windows/Web.
- כל יכולת שאינה ישימה ללא שינוי באפליקציות הדוגמה תסומן כפער מפורש ותטופל באמצעות הוספת מסך בדיקה ייעודי, לא באמצעות הצהרת כיסוי כוזבת.

## תנאי קבלה
- מניפסט עצמאי לכל שלב: מזהה חדש, פעולה, יעד, אסטרטגיית איתור, עוגנים, מסגרת, הקשר, בועית, אימות, לכידה, תנאי השלמה ותוצאה צפויה.
- בדיקת התאמת יעד חי לפני התקנה; אין שימוש בנתוני רשומה דינמיים מומצאים.
- יצירת Guide חדש בלבד בעסקה באופן מבוקר.
- הרצה רצופה מוצלחת מתחילה ועד סוף, עם תיעוד ראיות לכל יכולת.
- דוח שמבדיל בין מוגדר, נמצא ביעד, ונבדק בהצלחה.
- הקפאת המניפסט והייצוא לאחר הצלחה, לשם השוואה מול Instructor עתידי.

## מצב
נוצר והותקן במסד הנתונים מדריך ייחוס חדש ומשולב בשם `sampleapp-cleanroom-reference`, עם 31 שלבים ברצף Web → Windows → Web. הסקריפט `scripts/Create-Cleanroom-Reference-Guide.py` מאפשר התקנה חוזרת של אותו מדריך בלבד. טרם בוצעה רגרסיה מלאה למדריך החדש, וטרם אומת כיסוי כל יכולות המנוע. אין להסיק ממסמך זה יכולת או מגבלה של המנוע ללא בדיקת הקוד וההרצה.
