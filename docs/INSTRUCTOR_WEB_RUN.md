# GuideMe Instructor Web — הרצה ומצב מימוש

## הרצת הממשק החדש (Windows)

```powershell
cd C:\yossi\ChatGpt\DAP-Platform
git pull --ff-only origin main
dotnet build src\GuideMe.Instructor.Web\GuideMe.Instructor.Web.csproj
dotnet run --project src\GuideMe.Instructor.Web\GuideMe.Instructor.Web.csproj
```

הממשק נפתח בכתובת `http://127.0.0.1:53922` בדפדפן המקומי. אין צורך בשרת SampleApp ואין שינוי בפורטים של Learner.

## היכולות שכבר חוברו ל־V5

- הצגת רשימת לומדות וחיפוש.
- טעינת לומדה קיימת ורשימת השלבים.
- הצגת נתוני השלבים, רכיבי היעד והכללים לקריאה; עריכת טקסט בועית והפעלת/השבתת שלב ושמירתם ב־V5.
- יצירת לומדה עם הקשר אפליקציה ראשון (Web לפי UrlHost, Windows לפי ProcessName).
- שינוי שם לומדה.
- הוספת הקשר אפליקציה, שינוי שם תצוגה, החלפת זיהוי והסרת הקשר שאינו בשימוש.

המערכת משתמשת ישירות ב־`V5GuideReader` וב־`V5GuideWriter` הקיימים, ובמסד `C:\ProgramData\GuideMe\Data\GuideMe-V5.db`. המערכת אינה יוצרת או ממירה DB.

## גבולות הגרסה

- עריכת רכיבי יעד, תנאי התקדמות ושמירת לכידות כשלב V5 עדיין אינן זמינות בממשק.
- פרויקט WPF הישן הוסר; רכיבי V5 נמצאים כעת בתוך פרויקט Web Instructor.
- התוסף משתמש ב־Native Messaging ייעודי ומעביר את האירועים דרך Named Pipe אל Web Instructor.
- הממשק הוא עורך לומדות ושלבים; פעולות מתקדמות שטרם מומשו אינן מוצגות כאילו הן זמינות.
- אין לפתוח פורט לרשת. השרת מאזין רק ב־127.0.0.1 ומחייב אסימון סשן לקריאות API; פעולות שינוי דורשות JSON ובדיקת מקור. נדרשות בדיקות אבטחה לפני ייצור.
- לא בוצע Build על Windows מתוך סביבת העריכה. יש להריץ ולוודא מקומית.

## המשך

השלב הבא הוא להעביר לכידת Web ו־Windows לחוזי Host מקומיים ומצבי הקלטה, תוך שמירה על הפרדה מלאה מתוסף Learner. לאחר מכן עריכת שלבים מלאה ובדיקות יצירה־הרצה מול Learner.


## תוסף Instructor ללא ממשק משתמש — Native Messaging

ה־Instructor משתמש ב־Native Messaging נפרד מה־Learner:
- Host בשם `com.guideme.instructor` מפורסם תחת `C:\\GuideMe\\InstructorWeb\\NativeHost`.
- רישום Chrome נכתב ל־`HKCU\\Software\\Google\\Chrome\\NativeMessagingHosts\\com.guideme.instructor`.
- קובץ ה־Manifest נוצר תחת `%LOCALAPPDATA%\\GuideMe\\NativeMessaging`.
- ה־Host מתקשר עם Web Instructor דרך Named Pipe המוגבל למשתמש הנוכחי ול־Windows Session.
- התוסף אינו פונה אל HTTP ואינו מבקש קוד צימוד. פורט `53922` משמש לממשק הניהול המקומי בלבד.
- מנגנון ה־Learner וה־Host שלו אינם משתנים.

### פרסום והפעלה

```powershell
cd C:\\yossi\\ChatGpt\\DAP-Platform
git pull --ff-only origin main
.\\scripts\\Publish-GuideMeInstructorWeb.ps1
& "C:\\GuideMe\\InstructorWeb\\GuideMe.Instructor.Web.exe"
```

בדפדפן: `chrome://extensions` → GuideMe Instructor → Reload. מקור התוסף חייב להיות `C:\\GuideMe\\InstructorChromeExtension`. גרסת התוסף `0.4.0`.

### עריכת שלב

1. פתח את Web Instructor ובחר לומדה ושלב.
2. לחץ **עריכת שלב**. אפשר לשנות את טקסט הבועית ואת מצב השלב (פעיל/מושבת).
3. לחץ **שמירה**; מתבצע עדכון של שורת `Steps` לפי `GuideId + StepId`, ללא שינוי ברכיבי יעד, בכללים או בלכידות.

**אין פאנל הקלטה עצמאי**, גם לא בתוך פרטי השלב. מנגנון ה־Native Messaging נותר פעיל ברקע, וחיווי החיבור מוצג בכותרת. פעולות זיהוי רכיבים ותנאי התקדמות ייחשפו בתוך עורך השלבים רק לאחר השלמת המימוש והשמירה שלהן.

## אייקון Instructor

הפרסום משתמש בקובץ האייקון המקורי שנמסר על ידי המשתמש (`src/GuideMe.Instructor.ChromeExtension/instructor-source.png`), ללא ציור חדש. נוצרות גרסאות 16, 48 ו־128 פיקסלים. קובץ `icon48.png` שהופק מאותו מקור מועתק גם אל `C:\\GuideMe\\InstructorWeb\\wwwroot\\favicon.png` ומוגדר כ־Favicon של ממשק Web Instructor. סקריפט הפרסום מוודא התאמה מלאה של הקבצים באמצעות SHA256. Chrome עשוי להחזיק מטמון אייקונים גם לאחר רענון, ולכן נדרשת פתיחה מחדש של חלון Instructor לבדיקת האייקון בשורת המשימות.

## מחיקת לומדה קיימת

במסך פרטי לומדה קיים כפתור **מחיקת לומדה**. כדי לאשר מחיקה יש להקליד את שם הלומדה במלואו. ה־API מאמת את השם מול הנתון העדכני במסד הנתונים, ורק אז מפעיל את `V5GuideWriter.DeleteGuide` הקיים מה־Instructor הישן. הפעולה מתבצעת בטרנזקציה אחת ומוחקת את ישויות הלומדה בטבלאות V5 לפי סדר מפתחות זרים. היא אינה משנה לומדות אחרות. המחיקה בלתי הפיכה; יש לבדוק תחילה עם לומדת ניסוי בלבד, ולא עם לומדות Web/Windows המאומתות.

## מופע יחיד ומחזור חיים

Instructor מפעיל **שרת אחד וחלון Chrome ייעודי אחד לכל Windows Session**. נעילת Mutex מקומית לפי מזהה Session מתבצעת לפני פתיחת פורט 53922 או Named Pipe. הפעלה נוספת אינה יוצרת שרת או חלון חדשים: היא מאתרת חלון Chrome בעל כותרת Instructor ומנסה להביא אותו לקדמת המסך, ואז מסתיימת. אין סגירה של תהליכי Chrome ואין פגיעה בלשוניות אחרות או ב־Learner.

סגירת חלון Instructor מסיימת את השרת; חיבור WebSocket מאפשר להבחין בין סגירה לרענון (חלון חסד של 3 שניות). Ctrl+C סוגר את השרת ומבטל חיבורי WebSocket פעילים.

בדיקת Windows: פתח Instructor; הפעל את אותו EXE שוב וודא שהחלון הקיים מופיע בחזית, שאין חלון נוסף ושלא נפתח תהליך שרת נוסף. רענן את החלון ובדוק שהוא ממשיך לפעול; סגור אותו וודא שהשרת מסתיים. עדיין נדרש אימות מקומי.

## בחירת אפליקציות בלומדה

יצירת לומדה: הזנת שם ובחירת אפליקציות פתוחות מתוך לשוניות Chrome וחלונות Windows. מזהים נשמרים ב־V5 בטרנזקציה אחת. Web מזוהה לפי UrlHost, ו־Windows לפי ProcessName.

עריכת שלב קיים: ניתן לבחור אפליקציה מתוך אלה שמשתתפות בלומדה. באפליקציה יחידה הבחירה אוטומטית. השמירה מעדכנת את טקסט הבועית, מצב ההפעלה ושיוך האפליקציה בפעולה אחת.

מגבלות: אפשר ליצור שלבים ידניים חדשים; עדיין אין יצירת שלבים אוטומטיים עם רכיבי יעד או עריכת כללי התקדמות. במקרה של כמה חלונות מאותו תהליך או אתר אין להסיק בחירת חלון ייחודי בשעת הרצת Learner.

## יצירת שלב חדש

פתח לומדה ובחר **הוספת שלב**. הזן טקסט לבועית, בחר את מיקומה ובחר אפליקציית יעד רק אם הוגדרו כמה אפליקציות ללומדה. הבקשה שומרת רשומת Steps חדשה במסד V5 באופן טרנזקציוני, ומשייכת אותה ל־ApplicationContextId. כאשר אין רכיב יעד, מהדר ה־Learner מפרש זאת כשלב ידני; הממשק מציג הודעה מפורשת על מצב זה. אין לשנות לומדות רגרסיה מאומתות לצורך הבדיקה.

השלמת רכיבי יעד, תנאי התקדמות ולכידה אוטומטית היא עבודה נפרדת שלא נכללת עדיין בפעולה זו. ההגדרה הקיימת של הקלטת אירועים אינה מספקת עדיין בחירת רכיב ואימות שעברו אישור ושמירה ב־V5.

## בחירת רכיב Web ותנאי התקדמות

בשלב Web ללא רכיב יעד קיים מופיע **בחירת רכיב באתר**. Instructor מאתר לשונית מתאימה באמצעות המזהים השמורים ב־ApplicationContexts (במקרה של כמה לשוניות נדרשת בחירה מפורשת), ומפעיל בחירה חד־פעמית דרך תוסף Instructor ו־Native Messaging. המדריך מעביר עכבר מעל רכיבים בדף; הרכיב שמתחת לסמן מודגש במסגרת ובתווית. בחירה נעשית עם Ctrl+Shift+Space ללא לחיצת עכבר על הרכיב. Esc מבטל את מצב האיתור. סימון הרכיב מבוצע באמצעות CSS outline זמני על הרכיב עצמו (ללא שינוי פריסת הדף); הערכים הקודמים נשמרים ומשוחזרים בסיום.

ה־Content Script יוצר בורר CSS ייחודי בדף הנוכחי, ומחזיר אותו ל־Instructor להצגת רכיב לאישור. העורך מציע שני תנאי התקדמות הנתמכים בחוזה Learner: `clicked` ו־`target-disappeared`. לאחר אישור מפורש נשמרות באותה טרנזקציה הרשומות `Elements`, `StepTargets` ו־`StepRules` ומשתנה מיקום הבועית מ־`Center` ל־`Auto`, כאשר היה מרכזי. רכיב יעד קיים לא נדרס אוטומטית.

הבחירה זמינה בדף הראשי ובמסגרות iframe נגישות לתוסף, כולל מסגרות מקוננות. בזמן אישור הבחירה נוצר נתיב CSS של מסגרות, הנשמר ב־Elements.FrameContextJson בהתאם לחוזה המהדר הקיים. מסגרת ש־Chrome אינו מאפשר להזריק לתוכה קוד אינה ניתנת למיפוי, ואין ליצור עבורה נתיב חלקי. עדיין אין כאן הגדרות Windows UI Automation. בורר CSS ייחודי ברגע הבחירה אינו ערובה ליציבות לאורך שינויי DOM; יש לבצע רגרסיית Learner לפני שימוש בייצור. בחר תנאי `clicked` עבור פעולה של לחיצה, ולא תנאי קיום רכיב שכבר עשוי להתקיים לפני תחילת השלב. לומדות הרגרסיה הקיימות אינן משתנות אוטומטית.

בדיקת ניסיון: הפעל את SampleApp Web ואת Instructor, צור לומדת ניסוי, הוסף שלב, בחר את הרכיב באתר, אשר `clicked`, וודא שנוצרו רשומות בשלוש טבלאות V5 ושיש אפליקציית Web משויכת לשלב. יש להריץ את ה־Learner בלומדת הניסוי לבדיקת ההתקדמות בפועל. אין בדיקת Windows אוטומטית בסביבת העריכה הנוכחית.

### אבחון הפעלת בורר רכיב Web

אחרי לחיצה על **בחירת רכיב באתר**, אין להתחיל לבחור רכיב כל עוד Instructor מציג **מפעיל בחירת רכיב בלשונית**. רק לאחר שתוסף Instructor אישר הפעלת מצב הבחירה תוצג הודעת **הממפה פעיל**. ה־Service Worker מקבל אישור מפורש מ־Content Script. אם אין אישור במשך 5 שניות מוצג הסבר על רענון התוסף ועמוד היעד, ללא שמירה ב־V5. תוסף Instructor מחזיק את Heartbeat דרך ה־Service Worker בלבד; ה־Content Script אינו נסגר בגלל הודעת Heartbeat שלא קיבלה תשובה.

### איתור בתוך iframe

תוסף Instructor מזריק את קוד הממפה למסגרות Chrome הנגישות דרך `allFrames`, ומפעיל מצב בחירה באותה לשונית בלבד. בחירה מתוך iframe מועברת למסגרת האב; כל אב מזהה את iframe הילד לפי `event.source`, מוסיף בורר CSS ייחודי, ומעביר הלאה עד למסמך העליון. כך נשמר סדר המסגרות החיצונית→פנימית. אישור ב־Instructor שומר את הנתיב ב־FrameContextJson כרשימת Locator מסוג css. מסגרות מוגבלות על ידי הרשאות Chrome, כגון דפי chrome:// או מסמכים שהזרקה אליהם אינה מותרת, אינן נתמכות.

### נראות הממפה ובחירת מזהה יציב

הממפה אינו מציג באנרים מעל אפליקציית היעד או צביעת רקע. רק הרכיב שעליו מרחפים מסומן במסגרת כחולה דקה ללא מילוי. ה־outline נצבע על ידי Chrome בהתאם לתיבת הרכיב עצמה, ולכן אינו דורש חישוב קואורדינטות ידני בתוך iframe, בגלילה או בשינוי פריסה. מסגרות iframe וה־HTML/BODY/HEADER אינם מסומנים כרכיבי מעטפת גדולים; הרכיב בתוך המסגרת נבחר בממפה של אותה מסגרת. עבור מזהי CSS קיימת העדפה למזהה id ייחודי, ולאחריו data-testid, data-test, data-qa, name, aria-label ו־placeholder, ורק לבסוף נתיב מבני. כל הצעה נבדקת כייחודית בדף הנוכחי. יציבות מזהים לאורך שינויי DOM מחייבת בדיקת Learner.

## עריכת שלב בממשק לא־טכני

מסך השלב מציג בעברית את האפליקציה, טקסט ההנחיה, הרכיב שנבחר ותנאי ההתקדמות. טבלאות StepTargets ו־StepRules אינן מוצגות כ־JSON. אפשר לערוך טקסט הנחיה ומצב שלב, לבחור מחדש רכיב Web מתוך האפליקציה, ולשנות תנאי התקדמות קיים באמצעות טופס.

בחירת תנאי Web נתמכת לפי החוזה הנוכחי: `clicked` — לחיצה; `value-not-empty` — שדה מולא; `value-equals` — השוואה לערך מוגדר; `target-disappeared` — הרכיב נעלם. עריכת תנאי מעדכנת את StepRules באופן טרנזקציוני. בחירת רכיב מחדש מעדכנת את LocatorsJson ו־FrameContextJson ב־Elements ללא דריסה של כלל ההתקדמות. בבחירת רכיב חדש, עבור שדה הזנה מוצע כברירת מחדל 'הוזן ערך'. ערך צפוי נדרש רק בתנאי של התאמה לערך.

לא מומשו עדיין עורך תנאים משולבים (AND/OR), זיהוי שינוי מסך, בדיקת בקשת שרת או בניית תנאים מתוך הבדלי מצב לפני/אחרי. אין להציג אפשרויות אלה כפעילות לפני מימושן במנוע וב־Instructor. עדיין נדרשת בדיקת בנייה והרצה מקומית.
